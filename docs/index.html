herdr-oil

The directory listing is a text buffer. Rename, create, delete, move and copy by editing lines with vim keys, then :w. A fuzzy finder and live grep live in the same popup.

Install

Link it, bind three keys

Needs Rust (cargo). bat and ripgrep are optional; they power previews and grep when installed.

# clone, then link (the build hook runs cargo build --release)
git clone https://github.com/OWNER/herdr-oil
herdr plugin link "$PWD/herdr-oil"
herdr server reload-config
# ~/.config/herdr/config.toml
[[keys.command]]
key = "prefix+d"            # explorer
type = "plugin_action"
command = "herdr-oil.explorer"

[[keys.command]]
key = "prefix+shift+f"      # fuzzy files
type = "plugin_action"
command = "herdr-oil.finder"

[[keys.command]]
key = "prefix+slash"        # live grep
type = "plugin_action"
command = "herdr-oil.grep"

Options go in $(herdr plugin config-dir herdr-oil)/config.toml. See config.example.toml for the editor, open target, Trash or permanent delete, and display settings.

How :w works

Diff every buffer, then apply in three phases

Edits from all visited directories are planned together. Validation runs first, so a clash stops the save before any file moves.

Where the entry's id appears nowOperation
nowhereDELETE to the Trash, or permanently if configured
at its original path, plus other placeskept; every other place is a COPY
only somewhere elsefirst place is a MOVE (same folder shows as RENAME), the rest are copies
a line with no idCREATE; a trailing / makes a directory, a/b/c.txt creates parents
PHASE 1

Copy into staging

Copies are made first, while every source is still untouched, into hidden staging names.

PHASE 2

Moves and deletes, deepest first

A moved entry is parked inside the nearest folder that never moves. That makes swaps, case-only renames and "move the child out, delete the parent" safe.

PHASE 3

Land, shallowest first

Creates and staged entries land at their final paths, re-rooted under folders that were renamed. An occupied path is reported and the entry is put back.

Validation rejects two lines with the same name, a name that already exists and is not being vacated, moving a folder into itself, absolute paths, and an id line that was emptied. On macOS names are compared case-insensitively, which is how the session above caught DESIGN.md landing next to design.md.

Design notes

Defaults worth knowing, and current limits

Decision

Enter types into your shell pane

The default open = "auto" types $EDITOR file into the pane you opened the popup from, but only when that pane has no agent and only a shell in the foreground. Otherwise it opens a split to the right. Set open = "split" if you never want typing.

Decision

Keybindings

The suggested prefix d, prefix ⇧F and prefix / are free in herdr’s defaults. If a key does nothing, a built-in action on the same chord wins; set that built-in to "" in [keys].

Decision

Splits close with the editor

Split and tab targets run exec $EDITOR, so quitting the editor closes the pane. Typing into the origin pane does not use exec.

Decision

Confirm dialog stays on

Every save is reviewed by default. confirm = false skips it, except when something would be deleted.

Limit

No undo for applied changes

u undoes buffer edits only. Deleted files can be restored from the Trash; renames and moves have no history.

Limit

Relative symlinks keep their target text

Moving a relative symlink into another folder does not rewrite it, so it can break. The DESIGN.md move in the screens is an example.

Limit

Screens come from a regular pane

herdr gives popups no readable pane id, so the captures were taken in a normal herdr pane running the same binary.

Checked

Tested against real directories

The planner and apply engine tests run on temporary folders: swaps, case-only renames, nested renames, recursive copies with symlinks, and no leftover staging files.
